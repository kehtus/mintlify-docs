Proportion's smart contracts have been through an independent security audit by Beosin. Between audits the code is re-read by hand and re-run through automated analysis tools, AI-based ones among them, as it changes. Neither replaces an independent audit, and further audits are planned as the protocol evolves.

**Audit report:** [View the Beosin audit report](https://beosin.com/audits/Proportion_202603161420.pdf)

## Administrative security

<Info>
This section describes the administrative configuration the protocol is moving to. **It is not in force yet.** Today ownership sits with a single address, and none of the actions below waits for a delay: upgrades, factory changes, integration and risk-parameter changes can all be executed as soon as the owner submits them. Pausing can also be triggered by the relayer, while only the owner can unpause.
</Info>

Critical administrative actions will sit behind a 3-of-5 multisig and timelocks. Protocol parameters will move only inside bounds compiled into the contracts, and no single key will be able to execute a privileged action on its own.

### Planned timelock schedule

| Minimum delay | Changes covered |
| --- | --- |
| **72 hours** | `MainVault` and `ChallengeVault` implementation upgrades; `transferOwnership` and other governance-control changes; migrations that replace a core Vault implementation. |
| **48 hours** | `queueFactoryChange` / `executeFactoryChange` for funded accounts; `proposeFactory` / `setFactory` for Challenge checkout; trusted integration changes such as `setRelayer`, `setForwarder`, `setMainVault`, and `setChallengeVault`; `setRiskConfig`, market additions, leverage increases, and other changes that increase protocol risk. |

<Note>
  Defensive actions that reduce risk may be executed immediately: pausing the vault, cancelling a queued change, disabling checkout, removing a market, and lowering leverage. Unpausing or increasing risk waits for the applicable timelock.
</Note>
