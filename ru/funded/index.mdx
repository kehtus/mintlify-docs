> Капитал и реальная исполняемость на Hyperliquid. Правила и выплаты в контракте, не в кабинете фирмы.

Трейдер получает ончейн funded-аккаунт на Hyperliquid: глубокая ликвидность, без кастодиального логина, без скрытых условий после активации. Сделки идут на реальный капитал и реальную книгу Hyperliquid. Это проверяемо на каждом этапе.

В отличие от кастодиальной проп-фирмы, обычную прибыль здесь делят трейдер и билдер по зафиксированному `builderPoolBps`. Волт и протокол из неё не берут ничего. Их доход растёт с премии, подписки и конфискованного surplus, а не с того, что трейдеру отказали в выплате.

<Tip>
Доля прибыли, которую контракт уже начислил, фирме не принадлежит. Она не может произвольно отказать в выплате вне правил протокола.
</Tip>

## Как получить счёт

Funded-аккаунт открывает билдер, либо трейдер сам вызывает `activateFunded` (self-funded). Как билдер отбирает людей снаружи (evaluation, свой стор) это его продукт, не протокол.

Счёт привязывается к EVM-адресу трейдера на HyperEVM. Торговля идёт через API-кошелёк. Exchange Proxy подписывает Hyperliquid, сырой ключ трейдеру не выдаётся.

| | Спонсируемый | Self-funded |
|---|---|---|
| Кто платит `R + P` | Вызывающий. Он же `record.builder` | Трейдер |
| Принципал `A` | Из MainVault | Из MainVault |
| Daily drawdown | Есть | Нет |
| Время | Подписка 30 дней, может продлиться | Предоплата 1 / 7 / 30 дней |
| Обычная прибыль | Сплит по `builderPoolBps` | Те же формулы, оба куска трейдеру |

Lifetime-пол одинаковый. На self-funded нет дневного пола, внутри сессии путь шире.

Живой список рынков MainVault это единственный список. Правка whitelist счёт не закрывает. Новые входы вне списка отклоняются. Остаток на снятом рынке сворачивается.

```
активация → Active → торговля
                   → вывод профита (необязательно)
                   → закрытие → сеттлмент → claim
```

Закрытие одно. Клон снимает фактический торговый капитал Core `Q`. MainVault берёт замороженную запись и начисляет pull-леджер.
