Vault 收入来自费用，以及存入 Hyperlend 的闲置资本所获的利息。扣除损失后，LP 净收益可能为零或为负。

  <Card title="激活溢价" icon="percent">
    激活费 `P` 的 **50%**。`P` 按账户规模的一定比例计算，不以准备金为计算基数
  </Card>
  <Card title="订阅" icon="repeat">
    出资方账户续期费用的 **50%**（每期为 `A` 的 1.5%）。自费账户的预付激活费也由 Vault 与协议各分得 50%
  </Card>
</CardGroup>

所有者将闲置 USDC 存入 Hyperlend 时，利息累积在 hUSDC 余额中并计入 LP 净资产。

LP 不拿普通的交易员 /出资方利润。被没收的盈余由出资方与协议平分，vault 也不拿。未使用的 `R` 退给记录的准备金收款方：直接激活时为出资方，通过 ChallengeVault 激活时回到其中的出资方运营余额。例外：vault 有债务时，没收性关闭会从未使用的 `R` 中留下一部分偿还债务，见下文“Vault 债务”。

本金损失先消耗 `R`。若快照的 Core USDC `Q` 低于 `A − R`，超出准备金的部分成为 `reserveDeficit`，并按该 USDC 金额减少 NAV；结算不会因此被阻止。单份价格的变化取决于总份额数。该金额同时记为 Vault 债务，见下文。

## Vault 债务

Vault 把每笔 `reserveDeficit` 记为 **Vault 债务**。记录债务本身不增加 NAV：损失已经降低过 NAV，债务本身也不是资产，只有实际偿还才会带回资金。

偿还是一项不得已的措施，而且范围很窄：它只偿还 LP 已经承担的损失，在结算时自动执行，且没有保证。

这项措施适用于：账户因 `Drawdown` 或交易员自己的请求（`TraderRequested`）而没收性关闭，并且 vault 有债务。此时 vault 留下三个数额中最小的一个：债务、该账户未使用的准备金，以及账户已接受峰值利润（超过账户规模的部分）每 1 美元中的 30 美分（见[账户规则](/zh/funded/rules)）。

这笔钱来自出资方未使用的准备金，不会动用交易员的利润；自费账户中交易员就是出资方，因此会减少其自己的退款。其他关闭不偿还债务；仍有待处理利润提取的关闭、下限仍停留在 `A − R` 的账户也不偿还。

```
A = $1,000, R = $100, 已接受峰值 $1,200
$200 利润的 30%                               $60
Vault 债务                                    $20
Drawdown，Q = $955：消耗 $45，未使用 $55
vault 留下 min($20, $55, $60)                 $20
出资方退款                                    $35
```

偿还金额不会一次性计入份额价值，而是在 7 天内平均计入，因此关闭不会让份额价格立刻变动。当前债务可在 `MainVault` 通过 `vaultDebt()` 读取。

## 风险

<AccordionGroup>
  <Accordion title="相关性回撤" icon="waves">
    多个账户同时出现超出准备金的亏损时，累计损失可能超过 vault 已赚取的费用和利息，使 LP 份额价值低于其存入时的价值。
  </Accordion>
  <Accordion title="跳空 / 超调" icon="zap">
    权益跌破下限会触发关闭，但不保证最终收回的资金不低于该下限。Core 清算或价格跳空可能使实际收回的 `Q` 低于下限。超过准备金 `R` 的本金损失由 LP 承担，并记为 Vault 债务，之后的没收性关闭只能在有限范围内逐步偿还，见上文“Vault 债务”。
  </Accordion>
  <Accordion title="债务偿还缓慢或不完整" icon="hourglass">
    只有没收性关闭会偿还债务，而且有上限，所以偿还可能缓慢或不完整。新的 `reserveDeficit` 可能比偿还来得更快，已下降的份额价格也不一定会恢复。在少见的情形下，如果 vault 的资产低于仍在计入份额价值的偿还金额，LP 存款、退出和新的激活会停止，直到最后一次偿还被完全计入，最长 7 天；结算与派付领取不受影响。
  </Accordion>
  <Accordion title="交易员筛选与开户决策" icon="users">
    LP 不挑选交易员，也不决定账户参数。出资方的选择通过账户费用和超出准备金的损失影响资金池，并不简单与其拨付本金成正比。
  </Accordion>
  <Accordion title="智能合约" icon="file-code">
    代码库经过[独立审计](/zh/security)，但 MainVault 与 FundedAccount 仍有合约风险。已审计的 vault 实现也可能被升级。
  </Accordion>
  <Accordion title="Hyperliquid / HyperCore" icon="link">
    权益读取、成交和资金返回依赖 HyperCore 及其桥接机制。故障可能延迟关闭与结算；由此造成且超出出资方准备金的损失由 LP 承担。
  </Accordion>
  <Accordion title="Hyperlend" icon="landmark">
    存入 Hyperlend 的闲置 USDC 面临该池子的合约和流动性风险。Vault 将 hUSDC 计入 NAV，但如果池子不能返回所需 USDC，依赖赎回的 LP 退出会失败。出资方准备金及派付负债不会存入该池。
  </Accordion>
  <Accordion title="LP 退出" icon="lock">
    开放的账户不会锁定份额。退出后，`totalAllocated` 仍不得超过新 NAV 的利用率上限，默认 80%。退出还受未被负债占用的 EVM USDC、Hyperlend 可赎回资金及协议暂停状态限制；不能召回交易中的本金来满足退出。
  </Accordion>
  <Accordion title="治理" icon="settings">
    所有者（多签）可通过 `setRiskConfig` 修改参数，也可升级 MainVault，两者都需在时间锁中等待 72 小时。利用率、单账户占 NAV 比例和最大回撤有固定边界；账户规模和 vault 上限没有固定的经济上界。所有者或 relayer 可暂停 LP 退出，只有所有者可解除暂停；派付领取仍可用。
  </Accordion>
</AccordionGroup>
