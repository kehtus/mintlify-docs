---
title: "Правила протокола"
description: "Что протокол enforce'ит on-chain и что билдер не может смягчить"
---

Протокол сам следит за правилами funded-аккаунта. Билдер не может смягчить или обойти их. Он только выбирает параметры в разрешённом коридоре.

## Жёсткие правила

| Правило | Значение |
|---|---|
| Обычная прибыль | `builderPoolBps` билдеру, остаток трейдеру. Волт и протокол берут 0 |
| Конфискованный surplus | Билдер 40% / протокол 20% / LP остаток |
| Лок профита | 30% принятой пиковой прибыли, на lifetime и daily полах |
| Вывод | 3 прибыльных checkpoint-дня (≥ 0.70%) или профит ≥ 3% от `A` |
| Checkpoint | 1 день |
| Спонсируемый срок | Подписка 30 дней |
| Daily drawdown | Обязателен на спонсируемом счёте, отсутствует на self-funded |
| Кто может спонсировать | Любой с `R + P` |
| Рынки | Живой whitelist MainVault. Правка счёт не закрывает |

## Trailing floor

```
A = $1,000, D = 10%, принятый пик = $1,200
baseFloor  = $900
profitLock = $60
trailing   = $960
```

Intraday пики двигаются только после порога 1%. Checkpoint принимает любой более высокий lifetime-пик. После подтверждённого вывода пики сбрасываются на `A`.

## Daily drawdown

Это не флаг на активации. Если вы спонсируете другого трейдера, daily DD включён на половине `D`. Если трейдер платит сам, его нет.

Тот же пример, старт дня `$1,000`, дневной пик `$1,200` → дневной пол `$1,010`. Рабочий пол это максимум двух.

## TARGET

`targetProfit` ончейн. Ноль выключает. Порог `A + targetProfit` блокирует обычный вывод. Relayer пишет `TargetReached` и сохраняет обычный сплит.

## Whitelist

Живой список это правило для каждого Active счёта. Лишний размер сворачивается. Остальные live-рынки остаются торговыми. Аварийное закрытие всего счёта это Admin, и Admin сохраняет обычный профит close.

## Что остаётся вашим

Как отбираете трейдеров, что берёте с них снаружи и как брендируете программу. Свои более жёсткие фильтры до активации делаете сами. Когда `activateFunded` уже прошёл, защиту капитала ведёт протокол.

Комиссии Hyperliquid builder-code с funded-счёта идут на `protocolFeeReceiver`, не билдеру.
