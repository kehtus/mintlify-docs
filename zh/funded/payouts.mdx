普通利润是双向分成。Vault 和协议不拿其中任何一部分。

```
builderShare = floor(profit × builderPoolBps / 10_000)
traderShare  = profit − builderShare
```

`builderPoolBps` 在激活时锁定，10%-70%。20/80 是常见产品条款，不是协议常量。

自费时两个桶打到同一地址。交易员拿到 100%。

协议与 LP 的收入来自溢价、订阅和被没收盈余。不是来自保留利润的提取。

## 提取利润

利润是 `currentEquity − A`。不是高水位。

必须同时满足：

- 账户为 Active，期限仍有效
- 没有待处理的交易员关闭意向
- 尚未达到 TARGET
- 利润至少 $1
- 账户已平仓
- 有足够的可交易 Core USDC

然后满足以下任一：

- **3** 个盈利 checkpoint 日（权益相对上一次 checkpoint 至少增长 **0.70%**）
- 利润 **≥ `A` 的 3%**

请求会快照全部利润，并将 Core → EVM 桥接。`claimWithdrawal` 按分成支付：交易员剩余从克隆汇出，Builder 份额记入领取账本。

已证实的领取之后，峰值重置为 `A`。被拒绝的 Core 发送可以取消。已存储的峰值不会被削弱。

在一日自费期限上，第一次 checkpoint 要等到期限结束。期内提取只能走 3% 路径。

## 关闭

关闭原因只写入一次。下限决定何时开始。它们不是费用。结算只用快照的 `Q`。

| 原因 | 未提取的 `max(Q − A, 0)` |
|---|---|
| Drawdown | 没收 |
| TraderRequested | 没收 |
| TARGET | 普通分成 |
| 订阅到期 | 普通分成 |
| 订阅取消（赞助） | 普通分成 |
| Admin | 普通分成 |

已经进入待处理提取的利润保持既得。它从不混入 `Q`。即使是没收性关闭，这一块仍按 `builderPoolBps` 分成。

### 被没收的盈余

```
builder    = 40% of (Q − A)
protocol   = 20%
vault / LP = residual
trader     = 0
```

未使用的 `R` 退给 `reserveRecipient`。直接赞助时是 Builder，自费时是交易员。只有实际本金亏损才会消耗准备金。

### 自愿关闭

已平仓的所有者可以请求关闭。这只是意向，不是原因。Proxy 清空仓位和挂单后，relayer 提交 `TraderRequested`。如果还能提取，先提取并领取。

## 结算

```
principalLoss   = max(A − Q, 0)
reserveConsumed = min(R, principalLoss)
reserveRefund   = R − reserveConsumed
closeProfit     = max(Q − A, 0)
```

结算只记入固定收款方。它不会把 USDC 推出去。

任何人都可以调用 `claimPayout(recipient)`。资金只能到达该地址。多个账户可以汇总到同一收款方。

Vault 从溢价、订阅和被没收盈余拿到的部分已经在 NAV 里。它不进领取账本。

<Warning>
没收性关闭会把未提取的关闭利润清零。若账户仍符合条件，先提取并领取。
</Warning>
