Всё, чего нет в запретах ниже, разрешено: копитрейдинг, боты, новости, овернайт, выходные.

## Trailing drawdown

Lifetime-пол стартует с `A − R` и фиксирует 30% принятой пиковой прибыли.

```
trailingFloor = A − A × D / 10_000 + 30% × max(peak − A, 0)
```

Пример: `A = $1,000`, `D = 10%`, принятый пик `$1,200` → пол `$960`. Сам пик остаётся `$1,200`. Повторное касание той же отметки пол не двигает.

В пике хранится принятый equity. Intraday пик двигает только `syncRiskState` после роста на 1% от последнего принятого пика. 30% применяются только при расчёте пола. Пробой это строго меньше. Равенство полу допустимо. Equity ≤ 0 это всегда пробой.

Суточный `checkpoint` принимает любой более высокий lifetime-пик без порога 1%.

## Daily drawdown

Только спонсируемые счета. У self-funded дневного пола нет (`builder == owner`).

Дневной лимит это половина trailing-процента, тот же лок 30% на дневной пик:

```
dailyFloor = dayStart − dayStart × D / 20_000 + 30% × max(dailyPeak − dayStart, 0)
effectiveFloor = max(trailingFloor, dailyFloor)
```

Тот же пример, старт дня `$1,000`, дневной пик `$1,200` → дневной пол `$1,010`. Полы не складываются.

После подтверждённого вывода профита пики сбрасываются на `A`. Пока профит уже ушёл с Core или пришёл на EVM, вьюхи полов считают от `A`, чтобы успешный перевод не выглядел как Drawdown.

## TARGET

`targetProfit` это необязательная сумма USDC, замораживается на активации. Ноль выключает.

```
порог: currentEquity ≥ A + targetProfit
```

Прошлые выводы в TARGET не копятся. Сначала всегда проверяется drawdown. На пороге обычный вывод уже нельзя.

Счёт сам по TARGET не закрывается. Причину `TargetReached` пишет только relayer. Это неконфискующий close: обычный сплит сохраняется. Если владелец сам нажмёт close на пороге, это сначала намерение `TraderRequested` (конфискация). Relayer всё равно должен предпочесть TARGET.

## Рынки и плечо

Торговля только по живому списку перпов MainVault, с живым капом плеча этого рынка.

Правка списка счёт не закрывает и не становится причиной close. Прокси не пускает новые входы вне списка. Keeper сворачивает остаток на снятом рынке.

Глобального «максимум 5× иначе close» нет. Правила «чужой рынок → счёт закрыт» на клоне нет. `UnauthorizedAsset` и `LeverageBreach` сидят в enum из-за ABI, живой клон их не ставит.

## Срок

| Режим | Как платится | Когда время кончилось |
|---|---|---|
| Спонсируемый | Подписка 30 дней, 1.5% от `A` за период (округление вверх до 1 USDC), 50/50 волт / протокол | `checkpoint` может продлить в последние 3 дня, если комиссию можно взять из профита без пробоя полов. Отмена это флаг: close будет на следующем подходящем checkpoint и сохранит обычный сплит |
| Self-funded | Предоплата: 2% / 1 день, 4% / 7 дней, 8% / 30 дней | Без автопродления. Истечение сохраняет обычный сплит. Любой может оплатить `extendRental` (те же тиры, без нового `R`). Горизонт не дальше чем сейчас + 30 дней, поэтому 30-дневный тир нельзя накинуть на уже живой срок |

Первый спонсируемый месяц не спрятан внутри платы за активацию. Self-funded срок оплачивается сразу.

`cancelSubscription` на self-funded ничего не меняет. Раньше срока с сохранением профита там нет: либо дождаться истечения, либо `TraderRequested` (конфискация).

## Что выбирают на активации

- `A`: по умолчанию $10 – $20,000
- `D`: по умолчанию 5% – 25%
- `builderPoolBps`: 10% – 70% (в коде min 1000; дефолта нет, параметр обязательный)
- `targetProfit`: абсолютный TARGET или ноль
- `feeBps`: спонсируемый только 200 (2% / 30 дней). Self-funded: 200 / 400 / 800 → 1 / 7 / 30 дней

Daily drawdown параметром не передаётся: у спонсируемого он есть, у self-funded нет.
