---

Обычная прибыль делится на двоих. Волт и протокол из неё не берут ничего. Сплит фиксируется на активации и проп-фирмой после этого не меняется.

```
доля билдера = floor(profit × builderPoolBps / 10_000)
доля трейдера = profit − доля билдера
```

`builderPoolBps` в коридоре 10%-70%. Часто ставят 20/80. Это параметр активации, не константа протокола.

На self-funded оба куска идут на один адрес, трейдер получает 100%.

Протокол и LP зарабатывают на премии активации, подписке и конфискованном surplus при close. Не на обычном выводе.

## Вывод профита

Профит = текущий equity − `A`. High-water mark базой не является.

Нужно всё сразу:

- счёт Active, срок ещё жив
- нет намерения добровольного close
- TARGET не достигнут
- профит не меньше $1
- счёт плоский
- хватает торгового Core USDC

И одно из двух:

- 3 прибыльных checkpoint-дня (день считается, если equity вырос минимум на 0.70% к предыдущему checkpoint)
- или сразу: профит ≥ 3% от `A`

Запрос снимает весь профит и переводит Core → EVM. После прихода `claimWithdrawal` платит обычный сплит: остаток трейдера уходит с клона, доля билдера падает в pull-леджер.

После подтверждённого claim пики сбрасываются на `A`, серия прибыльных дней обнуляется. Отклонённую отправку с Core можно отменить, сохранённые пики не слабеют.

На однодневном self-funded сроке первый checkpoint совпадает с концом срока. Внутри дня вывод только через порог 3%.

<Info>
На спонсируемом счёте подписку можно отменить. Close будет на следующем подходящем checkpoint и сохранит обычный сплит.
</Info>

## Закрытие

Причина close пишется один раз. Полы решают когда закрывать. Пол это не комиссия. Сеттлмент смотрит только снапшот `Q`.

| Причина | Невыведенный профит close `max(Q − A, 0)` |
|---|---|
| Drawdown | Конфискован |
| TraderRequested | Конфискован |
| TARGET | Обычный сплит |
| Истечение подписки | Обычный сплит |
| Отмена подписки (спонсируемый) | Обычный сплит |
| Admin | Обычный сплит |

Профит, уже принятый в незакрытый вывод, остаётся закреплённым при любой следующей причине. В `Q` он не попадает. Даже на конфискующем close этот кусок делится по обычному `builderPoolBps`.

### Конфискованный surplus

```
билдер    = 40% от (Q − A)
протокол  = 20%
волт / LP = остаток
трейдер   = 0
```

Неиспользованный резерв возвращается `reserveRecipient`. На прямом спонсировании это билдер, на self-funded это трейдер. Резерв ест только фактический убыток принципала.

### Добровольный close

Владелец в flat может запросить закрытие. Это намерение, не причина. После того как прокси вычистит позиции и ордера, relayer коммитит `TraderRequested`. Если профит ещё можно вывести, сначала вывод и claim.

## Сеттлмент и клеймы

```
убыток принципала = max(A − Q, 0)
съедено резерва   = min(R, убыток)
возврат резерва   = R − съедено
профит close      = max(Q − A, 0)
```

Сеттлмент только начисляет фиксированным адресам. USDC сам никому не пушит.

Любой может вызвать `claimPayout(получатель)`. Деньги уйдут только на этот адрес. Несколько счетов могут копиться на одном получателе.

Доля волта от премии, подписки и конфискованного surplus в леджер не попадает, она уже в NAV.

<Warning>
Конфискующий close обнуляет невыведенный профит close. Если счёт ещё можно вывести, сначала вывод и claim.
</Warning>
